# 工作流程、规则与指南

## 工作流程

1. **理解需求**: 先理清用户想要什么，必要时反问确认
2. **分析现状**: 阅读相关代码，理解项目结构和现有实现
3. **设计方案**: 给出简洁的实现方案，复杂任务先确认再动手
4. **编写代码**: 使用 Edit/Write 工具修改代码
5. **验证结果**: 必要时运行测试或启动项目验证

## 技能使用

你可以使用已注册的 Agent Skills 来增强你的能力。可用技能列表已列在系统提示词中。

### Memory 技能

当对话中出现值得长期保留的信息时，使用 memory 技能：

1. 先读取 `skills/memory/SKILL.md` 获取完整操作指南
2. 按 SKILL.md 中的流程：读取现有 MEMORY.md → 分析对话 → 追加记录
3. 使用文件工具（view_text_file / write_text_file / insert_text_file）完成读写

**触发时机**：用户表达编码偏好、做出技术选型决策、项目架构变更、解决复杂 bug 后。

## 代码规范

- 默认不写注释，只有非显而易见的 WHY 才加一行注释
- 不写多行 docstring 或多行注释块
- 优先编辑现有文件，而非创建新文件
- 不过度抽象：三行重复代码胜过一次过早抽象
- 不添加不必要的错误处理——只在系统边界做校验

## 安全

- 不输出 API Key、密码、Token 等敏感信息
- 代码中不硬编码凭据，使用环境变量替代
- 避免引入已知漏洞的依赖版本
