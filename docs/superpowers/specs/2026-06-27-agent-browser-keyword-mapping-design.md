# Agent Browser 关键词映射设计

## 背景与目标

当前 `xufeng-material-navigator` skill 要求大模型直接生成页面路径，`agent_browser` 只负责补全域名并把路径写入导航 metadata。模型偶尔会生成不存在或错误的路径。

本次改动把 URL 的所有权移到 tool：大模型只提供页面关键词，tool 在受控页面注册表中进行容错匹配，并且只把注册表中的 URL 写入 metadata。

## 接口调整

`agent_browser` 的接口由：

```python
async def agent_browser(url: str, content: str) -> ToolResponse:
```

调整为：

```python
async def agent_browser(keyword: str, content: str) -> ToolResponse:
```

- `keyword`：页面、产品品类或产品牌号关键词，例如 `H13`、`冷作模具钢`、`联系方式`。
- `content`：展示给用户的简短页面说明，行为保持不变。
- 不保留旧 `url` 参数，避免模型继续生成不可靠路径。

## 页面注册表

`agent_browser.py` 内维护唯一页面注册表。每个条目包含：

- 规范页面名称；
- 一个受控 URL 路径；
- 可匹配的中英文别名；
- 页面类型或优先级，用于在通用分类页与具体产品页同时命中时选择更具体的页面。

注册表覆盖现有 skill 中的全部页面：32 款产品详情页、4 个产品分类页，以及首页、关于我们、产品中心、牌号对照表、产品规格表和联系我们。

## 匹配流程

1. 校验 `keyword` 非空。
2. 使用 Unicode NFKC、`casefold()` 归一化输入，并移除空格、点号、连字符、下划线等分隔符。
3. 对每个页面的规范名称和别名执行分层评分：
   - 归一化后完全相同：最高分；
   - 输入包含完整别名：次高分；
   - 使用 `difflib.SequenceMatcher` 计算相似度：基础分。
4. 输入同时包含具体产品与产品分类时，通过匹配层级、别名长度和页面具体程度优先选择产品详情页。
5. 选择总分最高的候选。相同分数按稳定的注册表顺序决定，保证结果可复现。
6. 最高候选相似度必须达到 `0.72`；否则匹配失败。

该流程应容忍大小写、分隔符和轻微拼写错误，例如 `SKD-11`、`SKD-1l`、`冷做模具钢`，但不能把明显无关的关键词映射到任意页面。

## 成功与失败行为

匹配成功时，tool 使用注册表 URL 生成与当前格式一致的 `ToolResponse`：

```json
{
  "action": "page_navigation",
  "payload": {
    "url": "/受控路径/",
    "content": "页面简介"
  }
}
```

匹配失败时抛出带有清晰提示的 `ValueError`。AgentScope 会把异常转换成 `Error: ...` 工具结果。失败结果不包含 `page_navigation` metadata，因此前端不会跳转。空关键词采用相同失败路径。

## Skill 调整

`xufeng-material-navigator/SKILL.md` 不再列出或要求模型生成 URL：

- 执行流程改为提取简短、明确的页面关键词；
- 工具调用参数改为 `keyword` 和 `content`；
- 示例改为 `agent_browser(keyword="M42", ...)`；
- 保留产品体系、硬度和典型应用信息，帮助模型选择准确关键词并生成介绍；
- 页面路径表改成页面/关键词说明，URL 映射只存在于 tool 中。

README 中的接口说明与实现原理同步更新。

## 测试策略

新增针对匹配函数和工具结果的单元测试，至少覆盖：

- 产品牌号和通用页面的精确匹配；
- 大小写、空格、点号与连字符归一化；
- 英文牌号和中文页面名的轻微错拼；
- 同时出现产品与分类关键词时选择更具体、得分最高的页面；
- 无关关键词和空关键词抛出错误；
- 成功 metadata 中的 URL 必须来自注册表；
- 失败时不产生导航 metadata。

不新增第三方运行时依赖，匹配仅使用 Python 标准库。

## 不在本次范围内

- 自动抓取官网并动态发现页面；
- 使用向量、嵌入或大模型进行二次匹配；
- 前端导航协议变更；
- 兼容旧 `url` 参数。
